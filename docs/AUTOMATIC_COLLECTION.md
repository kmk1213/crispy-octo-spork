# 웹사이트 자동 가격 조회 배포

이 버전은 웹사이트에서 검색어를 입력하면 Python 서버가 국내 사입처와 필리핀·베트남 판매처의 공개 검색 페이지를 요청하는 구조입니다. 브라우저와 `/api/collect`가 같은 서버에서 동작합니다. 방문자의 PC에 Python이나 실행 파일을 설치할 필요는 없습니다.

**현재 클라우드 환경에서는 쇼핑몰 8곳 모두 프록시의 `CONNECT 403`으로 차단되어 실제 상품 가격을 가져오는 데 성공하지 못했습니다.** 사이트 자체가 반환한 차단 응답인지도 확인하지 못했습니다. 구현·모의 응답 테스트와 실제 사이트 연동 성공은 구분해야 합니다. 서버를 게시해도 실제 수집 성공을 보장하지 않습니다.

## GitHub Pages와의 차이

GitHub Pages는 HTML·JavaScript 같은 정적 파일을 제공합니다. Python 서버를 실행하거나 서버의 환경 변수로 API 키를 보관할 수 없습니다. 브라우저에서 쇼핑몰을 직접 호출하는 방식은 쇼핑몰의 CORS 정책에도 영향을 받습니다.

자동 가격 조회에는 이 저장소의 Flask 서버를 실행하는 웹 호스팅이 필요합니다. 서버가 `/`에서 `web/` 화면을 제공하고, 같은 주소의 `/api/collect?q=검색어`에서 가격을 수집합니다. GitHub Pages 주소만 게시하면 자동 조회 서버가 생기지 않습니다.

## Render에 게시

[Render 배포 설정 열기](https://render.com/deploy?repo=https://github.com/kmk1213/crispy-octo-spork)

1. Render 계정으로 로그인하고 저장소 접근을 허용합니다.
2. `render.yaml`의 서비스 설정을 검토하고 생성합니다. 템플릿은 `plan: free`를 요청합니다. 해당 계정·지역·시점에서 무료 플랜을 사용할 수 있는지 Render 화면에서 확인해야 합니다. 유료 플랜으로 자동 전환하도록 설정하지 않았습니다.
3. 빌드와 시작이 끝나면 Render가 표시하는 사이트 주소를 엽니다.
4. `/api/health`가 정상 응답하는지, 사이트 검색에서 소스별 실제 가격 또는 실패 사유가 표시되는지 확인합니다. 헬스 체크 성공은 쇼핑몰 수집 성공을 의미하지 않습니다.

이 문서와 배포 템플릿을 추가한 것만으로 외부 서비스가 생성되거나 게시되지는 않습니다. 현재 Render 로그인·서비스 생성·공개 URL 접속은 검증하지 않았습니다. 템플릿은 `autoDeploy: true`로 설정되어 연결된 서비스에 GitHub 변경을 자동 배포하도록 요청합니다. 기존 서비스에는 Render에서 해당 설정이 적용되었는지 별도 확인해야 합니다.

실행 명령은 다음과 같습니다. `$PORT`는 호스팅 플랫폼이 제공합니다.

```sh
gunicorn --bind 0.0.0.0:$PORT --workers 2 --threads 4 --timeout 60 app:app
```

## Docker를 지원하는 호스팅

```sh
docker build -t sourcing-radar .
docker run --rm -p 8080:8080 sourcing-radar
```

기본 접속 주소는 `http://localhost:8080`입니다. 공개 호스팅은 HTTPS와 외부 URL을 별도로 제공해야 합니다. `PORT` 환경 변수로 컨테이너의 수신 포트를 바꿀 수 있습니다. 컨테이너는 비루트 사용자로 실행되며 의존성 설치에서 TLS 검증을 유지합니다. 현재 작업 환경에서는 Docker 이미지 빌드와 실제 컨테이너 실행을 검증하지 않았습니다.

## 네트워크와 선택적 네이버 키

서버에서 다음 호스트로 HTTPS 요청이 가능해야 합니다. 기존 허용 목록이 있다면 필요한 호스트를 추가하고 다른 항목을 보존하세요.

| 조회 대상 | 호스트 |
|---|---|
| 올리브영 | `www.oliveyoung.co.kr` |
| 다이소 | `www.daisomall.co.kr` |
| 쿠팡 | `www.coupang.com` |
| 네이버쇼핑 공개 검색 | `search.shopping.naver.com` |
| Shopee 필리핀 | `shopee.ph` |
| Shopee 베트남 | `shopee.vn` |
| Lazada 필리핀 | `www.lazada.com.ph` |
| Lazada 베트남 | `www.lazada.vn` |
| 네이버 공식 쇼핑 검색 API | `openapi.naver.com` |
| 네이버 금융 PHP·VND 매매기준율 | `finance.naver.com` |

네이버 공식 검색 API를 사용하려면 호스팅 서비스의 비밀 환경 변수에 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`를 설정합니다. 이미 주입된 변수가 있다면 재사용합니다. 키가 없어도 다른 공개 검색 소스의 요청과 기존 계산·엑셀 기능을 사용할 수 있지만, 각 소스의 실제 접근 가능 여부는 별도로 확인해야 합니다.

환율 조회에는 별도 API 키가 필요하지 않습니다. `/api/exchange-rates`가 네이버 금융의 공개 표에서 매매기준율을 읽고, 웹사이트가 시나리오별 통화에 자동 적용합니다. 100 VND 고시는 1 VND당 원화로 정규화합니다. 실제 접근은 현재 프록시 차단으로 미검증입니다. 자동 조회 실패 시 해당 자동 시나리오는 계산에서 제외하며 기존 수동·예시 환율을 네이버 환율로 재표시하지 않습니다. 엑셀에서 적용 출처·조회 시각·고시 단위와 계산 포함 여부를 확인할 수 있습니다.

키를 HTML·JavaScript·GitHub 저장소·배포 명령·채팅에 넣지 마세요. 공개 프런트엔드에는 비밀 API 키가 필요하지 않습니다. Render 템플릿에는 실제 키나 빈 비밀키 요구사항을 포함하지 않았습니다.

## 결과 확인과 제한

- 수집 요청은 서버에 정해진 쇼핑몰 호스트와 제한된 검색어·결과 수를 사용합니다. 사용자가 임의의 URL을 입력해 서버에서 가져오는 기능이 아닙니다.
- 검색 결과는 수집 시점에 페이지에서 확인할 수 있었던 표시 가격입니다. 옵션·수량·배송비·쿠폰·회원가·재고 조건에 따라 결제 가격이 달라질 수 있습니다. 전체 시장 최저가를 보장하지 않습니다.
- 실제 데이터를 얻지 못한 소스는 실패 또는 미확인으로 표시해야 합니다. 데모 상품이나 추정 가격을 실시간 결과로 대신 표시하지 않습니다.
- 로그인·CAPTCHA·접근 차단이 나타나면 해당 소스의 자동 수집을 중단합니다. 차단 우회·계정 자동 로그인·프록시 회전 기능은 제공하지 않습니다. 공식 API나 허용된 피드가 있으면 그 경로로 연결해야 합니다.
- 상품명만으로 동일한 모델·용량·묶음 수량이 확정되지 않습니다. 추천 TOP3와 수익 계산에 쓰기 전에 동일 상품 여부와 판매 조건을 확인해야 합니다.
- 필리핀·베트남 판매가, 적용 환율, 판매 수수료, 세금 충당액, 배송비는 각각 확인 가능한 값이 있어야 비교할 수 있습니다. 해외 가격 수집이 실패한 상태에서 실제 수익 추천이 검증되었다고 볼 수 없습니다.
- 사용자 입력과 작업 내역은 현재 브라우저 저장소에 남습니다. 다른 기기로 옮기려면 작업 백업 파일을 사용하세요. 호스팅 서비스가 재시작되어도 사용자 입력이 서버 데이터베이스에 저장되는 구조는 아닙니다.

수집 환경 문제를 진단할 때는 호스트·HTTP 상태·발생 시각만 남기고 API 키·쿠키·개인정보를 로그에 기록하지 마세요. 네트워크 정책의 `CONNECT 403`, 쇼핑몰의 HTTP 403·429, 페이지 구조 변경은 원인과 해결 방법이 서로 다릅니다.
